# Study Room

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Inferred from the existing product: students and small study groups reviewing course notes and past exams, often with a laptop and phone in the same session. No specific age, institution, or subject is assumed.

## Product purpose

Turn shared course material into cited discussion, timed confidence quizzes, and a session rundown with actionable revision steps.

## Mechanism

Questions retrieve specific uploaded passages. Participants see the same streamed answer and sources. Quizzes reward honestly reported probabilities with logarithmic scoring; session reports combine recorded quiz results and discussion signals.

## Constraints

Preserve all routes, account and membership rules, data contracts, source citations, study focus, upload limits, private quiz submissions, deadlines, exports, newsletter consent, and unsubscribe behavior. Next.js 15, React 19, Tailwind 3, Prisma/Postgres and a separate Socket.io server remain. PDFs require selectable text. Ended sessions cannot reopen. No new claims, paid services, production writes, or invented endorsements.

## Brand commitments

Retain the Study Room name and the previous violet/slate color palette, as explicitly requested during implementation. The user authorizes redesigned layout, typography, components and copy, and choosing a direction without approval. Voice should be specific, calm and helpful. Light and dark modes, keyboard operation and deliberate mobile layouts are required.

## Evidence

The repository contains real help and journal content, unit tests, and historical verification reports. There are no customer testimonials or approved photographic assets. Any explanatory diagram is clearly identified as an example, never as live user activity.

## Principles

Show the source; make uncertainty useful; keep shared and personal records distinct; support efficient reading and conversation; preserve privacy boundaries.

## Language and sign-in preferences

The user requests English and French throughout the interface, a styled language dropdown, and an icon button with two light/dark states. Google, Microsoft and GitHub OAuth must support both signup and login alongside email/password. The original violet/slate palette remains pinned. Provider credentials and a configured database are deployment requirements; do not invent live integrations.
